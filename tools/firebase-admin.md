# 마스터 콘솔 관리자 설정 (Firebase, 한 번만)

관리자 아이디는 **`admin0215` · `admin2016` · `admin2017`** 셋이다(코드 `MC_ADMIN_IDS`, 규칙 `acct/<아이디>/uid`).
서버는 "지금 로그인한 사람이 이 셋 중 한 계정의 주인인가"로 관리자를 판단하므로, 따로 UID 를 찾아 넣을 필요가 없다.
**비밀번호는 코드·GitHub 어디에도 적지 않는다.**

## 1. 규칙 붙여넣기
Firebase 콘솔 → 프로젝트 → **Realtime Database** → **규칙** 탭
→ 안의 내용을 전부 지우고 **`tools/firebase-rules.json` 내용을 통째로** 붙여넣기 → **게시**.

(기존 규칙 34개는 한 글자도 바꾸지 않았고, 아래 5개만 더했다)

| 경로 | 읽기 | 쓰기 |
|---|---|---|
| `tuning` (정식 수치) | 누구나 | 관리자 3명만 |
| `dev_tuning` (test 수치) | 누구나 | 관리자 3명만 |
| `tuning_log` (정식 적용 기록) | 관리자 3명만 | 관리자 3명만 |
| `admin_log` (모든 관리자 변경 내역: test 수치·정식 적용·공지·이벤트·우편) | 관리자 3명만 | 관리자 3명만 |
| `local_tuning`, `local_tuning_log` | 이 PC 테스트용 (local_acct/admin0215) | |

## 2. 관리자 계정 만들기 (규칙 게시 후 **바로**)
게임(정식이든 test 든 같은 계정)에서 **회원가입** → 아이디 `admin0215`·`admin2016`·`admin2017` 각각, 비밀번호는 정한 것.
- 아이디는 먼저 가입한 사람이 갖는다. 다른 사람이 먼저 가입하면 관리자 자리를 뺏기니 바로 만들 것.

## 3. 확인
test 서버(`/test/`) → `admin0215` 로 로그인 → F9 → **🚀 정식 적용** 탭에 초록색 **관리자 확인됨** 이 뜨면 끝.

## 다른 계정이 관리자 창을 열면
test 서버의 관리자 창은 누구나 열 수 있지만(test 전용 기능), 수치를 서버에 저장하거나 정식에 적용하는 것·공지·이벤트·우편은 서버 규칙이 관리자 3명만 허락한다.

## 관리자 아이디를 더하거나 바꾸려면
Claude 에게 말하면 `test/index.html` 의 `MC_ADMIN_IDS` 와 `tools/firebase-rules.json` 의 `acct/<아이디>/uid` 조건을 같이 고친다 → 규칙을 다시 게시 → 그 아이디로 **바로** 회원가입.
